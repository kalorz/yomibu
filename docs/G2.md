# G2: focused experimental sentence context

Choose an explicitly permitted lexical tuple and request two experimental
sentences with one command. An optional preview explains the offline selection
and exposes the exact outbound content. Neither operation accepts an exercise.
Contextual reading/sense, naturalness, comprehension and enjoyment are unverified.

## Use

The original synthetic [permission fixture](../tests/fixtures/focused/pet-rest.json)
is the complete version-1 example for 寝る / ネル / sleep / false. Copy or provide
that JSON explicitly; neither command discovers an inventory or imports a preview.

```sh
# Optional, entirely offline. Needs no dictionary, credential, client or runtime.
yomibu context-preview --permissions /tmp/g2-permissions.json --focus-entry 1
# Optional explicit redirection; the program itself does not save anything.
yomibu context-preview --permissions /tmp/g2-permissions.json --focus-entry 1 \
  --json > /tmp/g2-preview.json

# A separately authorized paid attempt; do not run merely to test installation.
yomibu generate-focused --permissions /tmp/g2-permissions.json --focus-entry 1 \
  --dictionary /path/to/pinned/system_core.dic --allow-model-call --json
```

`--allow-model-call` authorizes only that invocation. A preview does not reserve
or authorize a subsequent request. Each invocation selects from its own inputs;
identical inputs and selector revision give identical selections and body bytes.
Generation reports its actual context. There is no context-file import, interactive
confirmation, REPL, retained session or required review handoff. Both commands
ignore `--data-dir` without resolving it. All existing commands retain their limits.

## Explicit inputs and bounds

The permission file has exactly `version: 1`, `grammar: [description, ...]` and
`bindings: {vocabulary: [...], grammar: [...]}`, matching G1. Every vocabulary
entry requires `written_form`, `reading`, `sense`, `direct_object`; each grammar
binding requires `declaration_id`, `rule`. Every field is required. Unknown,
duplicate and missing fields, invalid JSON/UTF-8, unsupported versions, blank
strings/declarations and invalid bindings are errors. Preserve strings, booleans,
duplicates and entry order without normalization. Descriptions never grant rules.
Empty arrays grant nothing and cannot prepare these situations.

| Boundary | Inclusive limit |
| --- | ---: |
| Permission file (read at most limit + 1) | 4,194,304 bytes |
| Vocabulary entries | 10,000 |
| Each written form / reading | 256 UTF-8 bytes |
| Each sense | 1,024 UTF-8 bytes |
| Grammar declarations | 128 |
| Each grammar description | 1,024 UTF-8 bytes |
| Grammar bindings | 512 |
| Selected distinct tuples | 3 |
| Complete serialized provider body, including escaping | 16,384 bytes |
| Provider response body | 65,536 bytes |

Count and field bounds also apply to library selection, over the full inventory
including unselected entries. Existing G1/analyze files remain limited to 65,536
bytes. An oversized request fails; grammar is never dropped or truncated and no
alternate situation, split request or fallback is tried to fit the byte budget.

## Selection revision `g2-situations-v1`

One private compiled array contains three **original synthetic suggestions**.
They are not a verified situation catalogue, collocation evidence or permissions.
Tuple notation below means exact `written_form / reading / sense / direct_object`.

| Priority / ID | Exact guidance | Required slots, alternatives in order | Rules |
| --- | --- | --- | --- |
| 1 / `pet-rest` | A pet rests. Describe the selected pet sleeping. | Predicate: 寝る / ネル / sleep / false. Participant: 猫 / ネコ / cat / false, then 犬 / イヌ / dog / false. | TopicWa, PoliteNonPast |
| 2 / `pet-walk` | A pet moves about. Describe the selected pet walking. | Predicate: 歩く / アルク / walk / false. Participant: the same cat, then dog. | TopicWa, PoliteNonPast |
| 3 / `book-reading` | A person reads a book. Describe the selected person reading the selected book. | Predicate: 読む / ヨム / read / true. Participant: 学生 / ガクセイ / student / false, then 先生 / センセイ / teacher / false. Object: 本 / ホン / book / false. | TopicWa, ObjectWo, PoliteNonPast |

Any listed tuple can be the focus. `focus-entry` is a positive one-based local
entry number, never a spelling lookup. Keep an explicitly chosen duplicate focus
instance. For each proposed association, inspect every inventory entry with the
same written form: a different reading, sense or direct-object flag makes it
ambiguous. Identical copies are not ambiguous. Neither a focus index nor catalogue
priority resolves conflicting tuples.

Examine every situation in table order. Fix its focus slot to the chosen instance;
for each remaining slot choose the first available unambiguous exact alternative,
and its lowest input entry number among identical copies. Require all slot entries
and each bound grammar rule. Choose the first situation with all prerequisites.
Output focus first, then the remaining predicate, participant and object slots.
Every tuple occurs once. Independently check membership, focus, slot coverage,
order and size. No optional vocabulary is added; supports are prerequisites for
preparation but their use in model output is optional.

Unavailable decisions distinguish `focus_not_found`, `ambiguous_focus`,
`unsupported_focus`, `missing_support`, `ambiguous_support`, `missing_grammar`.
All three ordered situation decisions are retained, with typed reasons and local
entry numbers where applicable. No request exists for unavailable context.

Ready-context exclusions are grouped in this order: `duplicate_of_selected_tuple`,
`ambiguous_association`, `unused_slot_alternative`, `unsupported_tuple_variant`,
`outside_chosen_situation`. Numbers remain ascending within groups; empty groups
are omitted. Exclusion means unselected, not unknown. For unavailable context,
selected/excluded arrays are empty and the situation/request are null: the
situation decisions explain why no selection exists.

Unrelated inventory changes within the bounds do not change selected tuples or
request bytes. Reordering can change local numbers; choose the new focus position.
Relevant alternatives/conflicts can change selection or feasibility. “Feasible”
means only that these declared prerequisites exist.

## Data flow and transmission

```text
explicit input -> validated full permissions -> deterministic context
  -> immutable bounded bytes + SHA-256 -> one authorized provider attempt
  -> both unchanged candidates -> real pinned Sudachi + full-permission evaluation
  -> separate focus occurrence and context-use observations
```

Source progress, evaluator permissions, lexical focus and generation context are
separate. Selection grants nothing. Evaluation always uses the original complete
`EvaluationBindings` and `GrammarDeclarations`, including permitted but unselected
words. All supplied grammar descriptions and bindings travel in their original
order, with duplicates and one-based declaration IDs intact.

The 13 top-level fields preserve G1: `model: gpt-6-luna`, `service_tier: default`,
`reasoning: {effort: none}`, `max_output_tokens: 1024`, `store/background/stream:
false`, `truncation: disabled`, `tools: []`, `tool_choice: none`,
`prompt_cache_options: {mode: explicit}`, two-message `input`, and the existing
strict two-string `sentence_candidates` schema in `text`.

The compiled developer prompt revision is `g2-focused-sentence-v1`. It requests
exactly two nonblank sentences of at most 100 Unicode scalar values, asks for
focus/situation, treats supplied text as data, prefers selected vocabulary while
making supports optional, distinguishes guidance from full local permissions,
restricts grammar to explicit bindings and forbids permission/validation claims.
The user JSON contains **only**:

```text
version: 1
kind: focused_sentence_context
vocabulary: selected complete tuples, focus first
focus: { vocabulary_index: 1 }  # outbound subset index, not a local inventory ID
situation: { id, description, required_grammar }
grammar: complete original descriptions
grammar_bindings: complete original bindings
```

Also transmitted: authorization, content type and ordinary connection metadata.
No full vocabulary inventory, local entry numbers/exclusions, learner IDs/progress/
history, source examples, cache data, paths, dictionary contents or evaluations
are transmitted. Supplied selected labels and grammar are transmitted verbatim.

Preview reads only its explicit permission file and constructs no analyzer,
credential, HTTP client or runtime. Generation validates input, selection and
request bounds before loading the explicit pinned dictionary and resolving the
existing `OPENAI_API_KEY` environment value. No HOME/cache discovery, synchronization,
automatic setup, persistence, telemetry or credential-file lookup is added.
Library preparation is synchronous and performs no I/O. The runtime sends the
prepared bytes without reselection/reconstruction, sharing G1 transport and parser.

Connection and total deadlines remain 5 and 30 seconds. Redirects, proxies and
protocol retries are disabled. One attempt is not proof of transmission: a
connection failure can prevent the server receiving it. Malformed, refused,
incomplete, oversized or unsupported responses are rejected whole, including
wrong counts/types and duplicate/extra candidate payload fields. No trimming,
normalization, salvage, retry, fallback, repair, ranking or acceptance occurs.

## Observations and output

Preview JSON is version 1, kind `focused_context_preview`, status `ready` or
`unavailable`, with `selector_revision`, `focus_entry`, nullable `situation`,
ordered `{entry, role, reason, vocabulary}` selections, complete `grammar` and
`grammar_bindings`, ordered `{reason, entries}` exclusions, all three `situations`,
fixed `limitations`, and nullable `request`. A request has `method`, `url`,
`body_utf8`, `bytes`, `sha256`. Decode `body_utf8` to recover exact outbound bytes;
no credential is included. Text describes the same selection, exclusions,
prerequisites, retained grammar, limitations and JSON-encoded exact request.

Generation JSON is version 1, kind `experimental_focused_sentence_candidates`,
with `notice`, actual `context`, G1 `generation` provenance and two `candidates`.
Provenance adds local `focused_context` (`selector_revision`, `situation`,
`selected_entries`). Each candidate retains G1 index/text/analysis/assessment and
adds `focus_occurrence` and `context_usage`. Neither format dumps the full vocabulary
inventory; generation text groups exclusion numbers without expanding labels.
Both formats retain every evaluator finding and original UTF-8 spans. Controls
are escaped while Japanese stays readable and decoded strings stay unchanged.

Focus observations use whole C-mode dictionary forms, readings, POS/class and
original spans. No substring matching. Existing exact/base-to-regular-stem reading
comparison is reused. Noninflected and regular-stem evidence are distinct; 読み
covers only its lexical span, never the following ます. Every compatible occurrence
is retained in sentence order. Component-only evidence is ambiguous, never a
whole-focus occurrence. Out-of-vocabulary evidence, unsupported morphology,
reading disagreements and competing identities remain explicit.

| Focus status | Meaning |
| --- | --- |
| `observed` | Compatible whole-unit evidence with no focus-specific conflict or assessment failure; unrelated lexical uncertainty does not override it |
| `absent` | No potential focus evidence in assessable analysis |
| `ambiguous` | Conflicting reading/identity or component-only evidence |
| `unassessable` | OOV/unsupported evidence affects a potential focus, or unresolved lexical evidence prevents establishing absence when no occurrence was observed |
| `not_run` | Missing or structurally invalid analysis |

Precedence is `not_run`, detected focus ambiguity, focus-specific unassessability,
then `observed` when a compatible occurrence exists. With no occurrence, unresolved
lexical evidence yields `unassessable`; otherwise the status is `absent`.
Compatible occurrences/counts survive focus uncertainty.

The separate `completeness` field describes the lexical observations:
`complete` means the report has no lexical uncertainties, `partial` means it
retains at least one uncertainty, and `not_run` means analysis was unavailable or
structurally invalid. The text report prints the same completeness separately.
For example, `qzxvは寝ます。` with focus 寝る reports `observed`, `count: 1`, and
`completeness: partial`, retaining the 寝 span and the unrelated OOV span.
`qzxvは歩きます。` retains `unassessable` with zero occurrences; unknown evidence
cannot establish absence. Complete observations do not validate reading or sense.
Unrelated grammar uncertainty does not erase lexical observations. Valid analysis
can still be used after an evaluation error; invalid analysis is never sliced.
Missing focus changes no evaluator judgment and triggers no additional request or
candidate suppression.
**Contextual reading and sense are always not assessed.** Same-reading homographs
and unrepresented alternatives may escape these observations.

Context use reports relevant whole lexical units with original token evidence,
spans, local `entries` (dictionary-form matches), and `selected_evidence`,
`unselected_permission_evidence`, `no_permission_entry` or `unresolved` plus a
reason where uncertain. Recognized grammar tokens and punctuation are excluded.
These are membership observations, not new permission judgments. Missing
permissions keep the evaluator's Fail reason/span beside uncertainty. Book-reading
retains the unchanged object-combination safeguard.

| Result | Stdout | Stderr | Exit |
| --- | --- | --- | ---: |
| Ready preview | Complete report | Empty | 0 |
| Valid input, unavailable context (either command) | Reasons, null request | Summary | 1 |
| Malformed/oversized input or request | Empty | Contextual diagnostic | 1 |
| Both evaluations complete, including Fail/Inconclusive/absent focus | Both reports | Empty | 0 |
| Candidate execution error | Both texts and available results | Summary | 1 |
| Transport/whole-response failure | Empty | Sanitized diagnostic | 1 |
| Argument error/missing opt-in | Empty | Usage diagnostic | 2 |
| Help/version | Normal output | Empty | 0 |
| Output failure | Possibly partial | Diagnostic where possible | 1 |

## Cost and limits of the experiment

The planning audit dated 2026-10-05 recorded Standard GPT-6 Luna prices of
US$0.10/million input and US$0.50/million output tokens. The planning allowance of
32,768 input plus 1,024 output tokens estimates **US$0.0037888 before tax**.
This is below US$0.01 per attempt as an estimate, not a tokenizer-enforced billing
cap. Timeout/cancellation can leave remote completion and billing uncertain.
Coding-agent usage is separate. See official [model/pricing](https://developers.openai.com/api/docs/models/gpt-6-luna).

[Explicit caching](https://developers.openai.com/api/docs/guides/prompt-caching)
without breakpoints avoids cache reads/writes. `store:false` does not guarantee
zero retention. API data is not used for training by default unless opted in;
abuse monitoring normally retains content up to 30 days with exceptions. No
account access, funding, EU-only processing or Zero Data Retention claim is made;
see [data controls](https://developers.openai.com/api/docs/guides/your-data).

Implementation/draft-review authorization does not authorize a live model call,
purchase or merge. Any future one-attempt smoke requires separate authorization
and refreshed pricing plus final sanitized bytes/hash first; a failure consumes
the attempt. No smoke, private evidence access, holdout rerun or learner feedback
study is part of this implementation.

A1 remains a historical **no-go**: **24/24 outcomes, 120/120 judgments, 11/12 exact
negative reason/span matches**, frozen records and object safeguard remain intact.
G2 engineering tests do not establish better Japanese, comprehension or enjoyment.
A later separately proposed voluntary check of three to five sentences could ask
for paraphrases, unfamiliar/awkward portions and ease/enjoyment ratings. Keep
feedback local unless explicitly shared; it cannot repair A1's score.

The deferred learner bridge must address source reading representation versus
evaluator katakana, absent kana-only readings, reading/sense association and
sense-specific `direct_object` evidence. Eligibility, component kanji, glosses,
POS, source examples and similarity cannot manufacture those mappings.

## Rust notes for a Ruby developer

- A checked `VocabularyEntryId` distinguishes one-based local identity from a
  raw offset; neither spelling nor an index manufactures permission.
- `GenerationContext` borrows full immutable inputs and selected entries.
  `FocusedRequest` owns serialized bytes/hash while carrying those borrows, so
  selection cannot silently replace evaluation inputs during a call.
- Private construction and independent result validation protect selection
  invariants. Enums distinguish unavailable prerequisites, uncertainty, completed
  findings and execution errors instead of a boolean “accepted”.
- Provider composition reuses one concrete transport/parser. The executable owns
  files, credentials, runtime and rendering; no new dependency or selector trait
  is necessary for three compiled situations.
