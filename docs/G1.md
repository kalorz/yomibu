# G1 experimental sentence candidates

> Historical contract: G1 code and `generate-candidates` are retired. The commands
> and APIs below describe [48825a0](https://github.com/kalorz/yomibu/tree/48825a05b7a8d84a5109b7d3be9ed3f6093f2033);
> use that checkout for reproduction. Current usage is the [story path](STORY_GENERATION.md).
> See [generation history](GENERATION_HISTORY.md) for conclusions and archived fixtures.

G1 requests two short Japanese candidates in one explicitly authorized OpenAI
attempt and checks each locally. They **never become accepted exercises**, even
when every completed check says Pass. Naturalness, multiword expressions and
contextual reading/sense are unassessed. The object-combination safeguard still
reduces coverage for ordinary object sentences; permission failures keep their
original spans alongside uncertainty.

## Explicit use

Build with the repository toolchain and dependencies. Supply an already installed,
pinned dictionary and a UTF-8 JSON file. The original synthetic example is
[`dog-cat.json`](history/generation/g1-fixtures/dog-cat.json):

```json
{
  "version": 1,
  "grammar": ["です — nominal copula"],
  "bindings": {
    "vocabulary": [
      {"written_form":"犬","reading":"イヌ","sense":"dog","direct_object":false},
      {"written_form":"猫","reading":"ネコ","sense":"cat","direct_object":false}
    ],
    "grammar": [{"declaration_id":1,"rule":"NominalDesu"}]
  }
}
```

Set `OPENAI_API_KEY` in the invoking process's environment through your chosen
credential handling. Do not put the key in arguments, source, fixtures, logs or
committed files. The program does not read `.env`, credential files or a keychain,
or save the key. Missing/blank/invalid credentials fail after local input and
dictionary preflight. No paid request happens during that preflight.

**The following command is paid and sends the supplied declarations to OpenAI.**
Run it only when you intend to authorize that one attempt:

```sh
cargo run --release --locked --offline -- generate-candidates --allow-model-call \
  --dictionary target/a1/current/system_core.dic \
  --input tests/fixtures/generation/dog-cat.json --json
```

Omit `--json` for readable text. Cargo's `--offline` controls dependency access;
unlike `analyze`, **`generate-candidates` makes the explicitly requested network
call**. Every invocation requires `--allow-model-call`; no saved opt-in exists.
The input path is mandatory. `--dictionary PATH` selects fully verified owned
bytes; omit it to use the [managed dictionary](DICTIONARY.md), optionally with
`--dictionary-dir PATH`. Only managed selection resolves its HOME default.
`--data-dir` is ignored. There is no stdin input, implicit learner access,
synchronization or dictionary setup during generation.

Use `--release` for interactive use. The first optimized build takes longer to
compile; Cargo reuses it while source and build inputs remain unchanged. Every
external-path invocation still reads, verifies and initializes the roughly 217 MB
dictionary before contacting OpenAI. Managed loading uses installation-time full
verification and startup checks before mapping. External loading is much slower in the default,
unoptimized development build. Provider waiting time is additional; `--release`
does not change what is sent or how candidates are assessed.

Illustrative text, not a captured provider result:

```text
Experimental sentence candidates — not accepted exercises
...
Candidate 1: "犬です。"
...
Overall: Pass (completed)
Vocabulary: Pass
...
Candidate 2: "猫です。"
...
Naturalness: not assessed
```

The sentences mean “It's a dog” and “It's a cat.” Actual candidates can differ,
fail checks or remain inconclusive. Both are retained, including duplicates; no
winner is selected. A blank/overlong candidate is an execution error and does not
erase the other candidate's checks. A malformed/incomplete/refused provider
response is rejected as a whole, without salvaging text.

Input uses existing analyze binding semantics but has no `sentence` field. All
fields are required; unknown/duplicate fields and other versions are errors.
Input is limited to 65,536 bytes and candidates to 100 Unicode scalar values.
No trimming/normalization occurs. Description order/duplicates and complete word
tuples are preserved; empty arrays grant nothing. Descriptions never create
bindings. Words are permissions, not mandatory targets. Readings use the existing
dictionary-style katakana guidance; sense/transitive-use labels are assertions.
See [SPEC's complete contracts](https://github.com/kalorz/yomibu/blob/48825a05b7a8d84a5109b7d3be9ed3f6093f2033/SPEC.md#g1--experimental-single-sentence-candidates)
and the [seven existing rule names](../README.md#analyze-one-supplied-sentence-offline).

## Results and failure semantics

Text includes both candidates, all completed checks, coverage, reasons and escaped
affected text with original half-open UTF-8 **byte** spans. It also displays pinned
analyzer/dictionary/configuration and generation provenance. Byte offsets refer to
the original text, not the escaped display. JSON decoding recovers original strings.

JSON has `version`, `kind`, `notice`, exact decoded `input`, `generation`, and two
`candidates` with one-based `index`, `text`, nullable `analysis` and `assessment`.
Completed assessments contain `status: "completed"`, the existing externally tagged
`outcome` (for example `{"Completed":"Fail"}`), and the full unchanged `evaluation`.
Execution errors contain `status: "execution_error"`, `stage`, `code`, `message`,
and `checks: [{"kind":"Vocabulary","state":"NotRun"}, ...]` for all five kinds.
No completed outcome or fake evaluation is supplied. Analysis survives if only
evaluation failed. Stable error codes are:

| Stage | Codes |
| --- | --- |
| sentence | `blank_sentence`, `sentence_too_long` |
| analysis | `analysis_failed`, `invalid_analysis_span` |
| evaluation | `blank_vocabulary`, `missing_declaration`, `invalid_analysis` |

Generation records `provider`, `requested_model`, `returned_model`,
`requested_tier`, `returned_tier`, `prompt_revision`, `request_sha256`,
`request_bytes`, `response_id`, `request_id`, `request_count`, and `usage`.
Optional metadata is `null`; usage, when present, has provider-reported
`input_tokens`, `output_tokens`, `total_tokens`. Returned model/tier and usage
are provider reports. The alias is not an immutable snapshot, and these counts
are not an independently verified bill.

| Exit | Meaning |
| --- | --- |
| 0 | Both evaluations completed, including Fail/Inconclusive; or help/version |
| 1 | Any execution/input/provider/output error |
| 2 | Argument error, including absent opt-in or paths |

Completed reports use stdout with empty stderr. Candidate execution errors retain
both texts and other available results on stdout plus a concise stderr diagnostic.
Preflight and whole-response errors leave stdout empty. An output-device failure
may leave partial stdout; writing is not atomic. Untrusted fields are escaped
without flattening help or diagnostic layout. Raw provider bodies, refusal text,
credentials and HTTP dependency chains are excluded from diagnostics.

## Provider, data and spending

The runtime is OpenAI Responses, `gpt-6-luna`, Standard processing, reasoning
`none`. This is independent of the coding agent. There are no provider/model
overrides, extra moderation calls, retries, fallback models, repair or judges.

| Bound | Value |
| --- | --- |
| Attempts per invocation | At most 1; a connection failure may prevent transmission |
| Candidates | Exactly 2 |
| Request bytes | 16,384, serialized once and hashed before sending |
| Output tokens | 1,024, including any reasoning tokens |
| Connection timeout | 5 seconds |
| Total HTTP deadline, including body | 30 seconds |
| Response bytes | 65,536, enforced for declared and streamed size |

Oversize requests fail before transmission without dropping permissions or
splitting the call. Redirects, environment/system proxies and reqwest's own retry
policy are disabled. Timeout/cancellation may still leave a billable provider
operation; neither establishes that nothing happened remotely.
The pinned client's [never-retry policy](https://docs.rs/reqwest/0.13.5/reqwest/retry/fn.never.html)
also disables its protocol-level retries, independently of application logic.

Settings explicitly include `service_tier: default`, `reasoning.effort: none`,
`max_output_tokens: 1024`, `store: false`, `background: false`, `stream: false`,
`truncation: disabled`, `tools: []`, `tool_choice: none`, and
`prompt_cache_options.mode: explicit` with no breakpoints. The last setting
disables cache reads/writes under the documented explicit-cache behavior.
Strict JSON Schema requests only two strings, but local parsing and sentence
validation remain authoritative. `g1-sentence-v1` is a compiled prompt revision.

Sent data is exactly the supplied vocabulary forms/readings/sense labels and
`direct_object` assertions, free-form grammar and bindings, fixed instructions,
schema/settings, API authorization and ordinary connection metadata. Dictionary
bytes, local paths, learner state, evaluation reports, private/held-out evidence
and this conversation are not sent. The API is not trained on submitted content
by default. `store:false` does not mean zero retention: abuse monitoring normally
retains content up to 30 days, with legal/safety exceptions. No EU-only processing
or Zero Data Retention claim is made.

Official documentation verified during planning on **2026-10-04**:

- [Model and prices](https://developers.openai.com/api/docs/models/gpt-6-luna):
  US$0.10 per million input tokens, US$0.50 per million output tokens.
- [Responses settings](https://developers.openai.com/api/reference/python/resources/responses/methods/create),
  [structured output](https://developers.openai.com/api/docs/guides/structured-outputs),
  [prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).
- [Data controls and retention](https://developers.openai.com/api/docs/guides/your-data).
- [Usage tiers](https://developers.openai.com/api/docs/guides/rate-limits) and
  [spending controls](https://developers.openai.com/api/docs/guides/spend-limits).

Using the planning allowance of 32,768 input tokens plus 1,024 output tokens gives
`32768 × $0.10 / 1000000 + 1024 × $0.50 / 1000000 = $0.0037888` before tax.
That input count is an estimate, **not an enforced tokenizer count or guaranteed
dollar cap**. The program enforces byte/output-token bounds and reports usage;
it adds no tokenizer request, billing calculator, spending ledger or automatic
price lookup. Prices may change; check before authorizing a live test.

Reserve **US$5 plus applicable tax for account funding when needed**, distinct from
the estimated under-US$0.01 request cost. Tier 1 documentation lists US$5 paid;
this does not verify a particular account's checkout minimum or access. Existing
credit/billing may suffice. Account purchases, automatic recharge and billing
setting changes are not authorized by implementation approval. Spending alerts do
not stop requests; provider hard limits may have enforcement delay. Local tests
incur no Yomibu provider charges; coding-agent usage is separate.

## Library and evidence boundaries

Direct callers explicitly construct `openai::Client`, call its async
`generate_candidates(&grammar, &bindings)`, then synchronously call
`generated.assess(&analyzer)`. No CLI, store, environment discovery or library-owned
runtime is needed. See the compiled direct-library example in
[`generation.rs`](../src/generation.rs). The caller is responsible for authorizing
each invocation and owning a Tokio runtime with I/O/time enabled.

Local tests use the real HTTP adapter and pinned linguistic adapter. The CLI test
harness supplies a concrete loopback constructor to the same entry function; it
ships no endpoint override or fake production response path. Synthetic credentials,
isolated directories and original CC0 cases keep tests independent and parallel-safe.
No dictionary dependency is skipped or replaced if unavailable.

A1 is complete with its historical no-go, **24/24 outcomes, 120/120 judgments and
11/12 exact negative reason/span matches**. G1 does not rerun holdout, edit frozen
references, read private evidence/learner data or start a linguistic review round.
The implementation only adds integration evidence. Later validated generation
still needs separately authorized acceptance evidence/rules and naturalness review.
Stories, quizzes, new grammar, idiom detection, automatic repair/retries/fallbacks,
learner-cache access/sync/discovery, dictionary setup, persistence and telemetry
remain excluded.
